## 2. 回顾本轮预期

本轮开始前，我们有三个主要判断。

### 预期 1：高价裁剪仍然值得继续挖

依据：

- 上一轮未裁剪 `optimized_weight_blend` 是 `0.12173`
- 上一轮裁剪后是 `0.11865`
- 裁剪带来 `0.00308` 提升

因此我们预期：更细地调整裁剪上限，可能继续提升。

### 预期 2：保守融合可能比单一 optimized 更稳

依据：

- 上一轮 `simple_blend.csv` 是 `0.12153`
- 上一轮 `optimized_weight_blend.csv` 是 `0.12173`

虽然 optimized 本地 CV 更好，但 Public Score 略差，所以我们怀疑 OOF 权重搜索有轻微过拟合，simple 的稳健性可能有价值。

### 预期 3：软压缩可能比硬裁剪更自然

硬裁剪会把超过阈值的预测都压成同一个上限，可能伤害真实高价房。

因此我们测试了：

```text
opt_soft_q995_s035
```

也就是超过 q995 的部分只保留 35% 尾部。

## 3. 实际结果验证

### 结论 1：高价硬裁剪方向继续有效

同一 `optimized_weight_blend` 预测下，不同裁剪上限表现如下：

| 裁剪方案 | 上限 | Public Score |
| --- | ---: | ---: |
| q997 | 572998.30 | 0.11865 |
| q995 | 527331.92 | 0.11818 |
| q993 | 473189.50 | 0.11805 |
| q990 | 442567.01 | 0.11841 |

观察：

- 从 q997 降到 q995，分数变好。
- 从 q995 降到 q993，继续变好。
- 从 q993 降到 q990，开始变差。

结论：

当前最合适的高价上限大概在：

```text
q990 和 q995 之间，更靠近 q993
```

也就是大约：

```text
47 万左右
```

这是本轮最重要发现。

### 结论 2：裁剪不是越狠越好

`q990` 的上限是：

```text
442567.01
```

Public Score：

```text
0.11841
```

它仍然优于上一轮 q997，但差于 q993。

说明：

- 高价预测确实偏高。
- 但测试集中仍然存在一部分真实高价房。
- 如果上限压得过低，会开始低估这些样本。

因此下一轮不要盲目继续往下压，而应该在 q992-q994 附近做精细搜索。

### 结论 3：软压缩不如硬裁剪

`opt_soft_q995_s035` 的 Public Score：

```text
0.11947
```

明显差于：

```text
opt_clip_q995: 0.11818
opt_clip_q993: 0.11805
```

说明当前模型的高价尾部不是“稍微偏高”，而是仍然有明显过估。保留尾部反而伤害分数。

结论：

短期内硬裁剪比软压缩更值得继续。

### 结论 4：保守融合有收益，但不是主收益

保守融合结果：

| 文件 | Public Score |
| --- | ---: |
| `mean_opt_simple_inverse_clip_q997.csv` | 0.11837 |
| `mix50_opt_simple_clip_q997.csv` | 0.11842 |

它们都优于上一轮 q997 best：

```text
0.11865
```

但都不如：

```text
opt_clip_q993: 0.11805
opt_clip_q995: 0.11818
```

说明：

- 保守融合确实有一点帮助。
- 但目前主要收益仍来自高价上限调节。

后续可以继续做保守融合，但应和 q993 附近裁剪结合，而不是只保持 q997。

- `NridgHt`、`NoRidge`、`StoneBr`：上限 q995
